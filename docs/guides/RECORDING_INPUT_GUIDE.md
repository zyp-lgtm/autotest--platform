# 录制功能使用指南 - 输入操作捕获

## 📝 重要提示

### 防抖机制说明
录制功能使用了**500ms防抖机制**来合并连续的输入操作：
- 当您在输入框中输入时，系统会等待 500ms
- 只有在停止输入 500ms 后，才会记录最终值
- 这样可以避免每个按键都被记录，只记录最终结果

### ⚠️ 常见问题

**问题**: 输入操作没有被捕获

**原因**: 停止录制太快，输入的防抖时间还没到

**解决方法**:
1. ✅ 输入完成后，**等待 1 秒钟**再停止录制
2. ✅ 或者点击页面其他位置，让防抖完成
3. ✅ 或者按 Tab 键切换到下一个输入框

## 🎯 正确的录制流程

### 步骤 1: 启动录制
1. 打开录制向导
2. 输入场景名称
3. 点击"开始录制"
4. 浏览器会自动打开

### 步骤 2: 导航到测试页面
1. 在浏览器地址栏输入测试网址
2. 等待页面完全加载
3. 系统会自动记录导航操作

### 步骤 3: 执行操作（注意输入）
1. **点击输入框** - 系统记录点击
2. **输入内容** - 例如 "test user"
3. **⏰ 等待 1 秒** ⚠️ 重要！
4. **点击其他元素或按 Tab** - 让防抖完成
5. 系统会记录输入操作

### 步骤 4: 停止录制
1. 确认所有操作完成
2. 确保所有输入的防抖都已完成
3. 回到向导点击"停止录制"

## 💡 优化建议

### 如果防抖时间太长
可以调整防抖时间（需要修改代码）:

```python
# 文件: app/services/recorder.py
# 第 368 行（大约）
}, 500);  # 500ms 防抖

# 可以改为:
}, 300);  # 300ms 防抖（更快但可能捕获更多中间值）
```

### 如果想看到实时输入
可以考虑禁用防抖（不推荐）:
```python
# 直接记录，不使用防抖
window.__recording.captureAction({
    action_type: 'input',
    selector: selector,
    value: e.target.value,
    // ...
});
```

## 📊 防抖时间对比

| 防抖时间 | 优点 | 缺点 |
|---------|------|------|
| 500ms (当前) | 准确捕获最终值，避免中间值 | 需要等待较长时间 |
| 300ms | 较快完成，仍能合并大部分输入 | 可能捕获一些中间值 |
| 100ms | 实时性好，用户体验好 | 会捕获很多中间值 |
| 0ms (禁用) | 完全实时 | 会记录每个按键，数据量大 |

## 🐛 调试技巧

### 如何确认输入是否被捕获
在浏览器控制台查看日志:
```
[录制] input #searchInput => test
[录制] 输入去重完成: #searchInput => test
```

### 如何手动测试
1. 打开录制浏览器
2. 在控制台输入:
```javascript
window.__recording.actions.length
```
3. 查看返回的操作数量
